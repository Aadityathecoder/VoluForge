# VoluForge Project Plan

This folder is the planning source of truth for completing and demonstrating the VoluForge MVP during Fall 2026.

## Planning files

- [availability.md](availability.md) — calendar, weekly capacity, reduced-efficiency periods, sick-day allowance, and assumptions
- [estimation-assumptions.md](estimation-assumptions.md) — AI-assisted estimation method, buffer, and velocity updates
- [system-architecture.md](system-architecture.md) — MVP platform choices and deployable architecture
- [project-plan.md](project-plan.md) — milestones, tasks, dependencies, dates, feature mappings, and definitions of done
- [progress-tracker.md](progress-tracker.md) — weekly status and velocity log
- [project-tracker-import.csv](project-tracker-import.csv) — task list that can be imported into a project tracker

## Baseline

- Planning baseline created: September 21, 2026
- Work starts: Monday, September 28, 2026
- Feature-development cutoff: Sunday, November 29, 2026
- Demo stabilization: November 30–December 10, 2026
- Assumed submission/demo deadline: Friday, December 11, 2026

The deadline and personal blackout dates are provisional because they were not supplied when this baseline was created. Update `availability.md` first when those facts become known, then reforecast the dated plan.

## Scope decision

The semester target is a thin, testable vertical slice of F01–F09: a nonprofit is approved, publishes an opportunity, a student discovers and applies, the nonprofit accepts, the student submits service, the nonprofit verifies it, and the student downloads a verified record. Advanced variants and polish cannot displace this core loop.

## Tracking workflow

GitHub Issues is the primary task system. Each issue should have one status (`Backlog`, `Ready`, `In progress`, `Blocked`, or `Done`), one milestone, and the relevant feature IDs. Update [progress-tracker.md](progress-tracker.md) at the end of each week.
